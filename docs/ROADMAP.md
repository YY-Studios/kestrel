# 로드맵

이 프로젝트는 한 번에 다 만들지 않는다. 단계적으로 확장하되, **각 단계는 앞 단계가 실제로 동작하고 검증된 뒤에만 시작한다.** 검증되지 않은 단계를 미리 당겨 만들지 않는다.

> **설계 철학: 규칙은 코드가 집행하고, AI는 분석·제안만 한다. 전략 변경과 주문 실행은 항상 사람의 승인을 거친다.**
> 이는 ADR-005("실전은 의도된 마찰을 거쳐 켠다") 정신을 AI 레이어로 확장한 것이다. 자동화의 편의가 "사람이 모르는 사이 돈이 움직이는" 위험을 넘지 않게 한다.

현재 합의된 방향: 한국투자(KIS) 해외주식 API로 **미국 주식**을 자동매매, 전략은 시나리오 1, **모의투자(paper) 우선**. (docs/PRD.md · docs/ADR.md 참고)

---

## 금지된 전략 (전 단계 공통)

아래는 단계와 무관하게 **항상 금지**한다. 어떤 단계도, 어떤 AI 레이어도 이 선을 넘지 않는다.

- **물타기(평단가 낮추기, averaging down) 금지.** 손절선(−3~5% 또는 60일선 이탈)을 넘긴 추가 매수는 시스템 차원에서 금지한다. **손절은 항상 집행된다.** 지는 포지션에 자금을 더 넣어 리스크 한도를 무력화하지 않는다.
- **분할매수 ≠ 물타기.** 분할매수는 **손절선 안에서** 진입을 나누는 것이고, 물타기는 **손절선을 부정**하는 것이다. 둘은 다르다. 분할매수 3회(40/30/30%)는 손절선이 살아 있는 상태에서만 유효하다.
- **손절 후 재진입은 허용.** 손절된 종목이라도 다시 1단계(추세 확인)부터 조건을 처음부터 만족하면 **새 포지션**으로 재진입할 수 있다(같은 포지션의 연장이 아니라 신규 진입).
- **4차 제약.** 4차 Hermes를 포함한 **어떤 AI 레이어도 물타기를 제안할 수 없다.** 단기 승률이 올라 보여도 꼬리 위험(tail risk)으로 계좌를 파괴하기 때문이다.

## 1차 (MVP) — 규칙 기반 자동매매: 시나리오 1

결정론적 규칙으로만 동작한다. **LLM 판단 없음.** 그래서 동작이 재현 가능하고 백테스트·검증할 수 있다.

> **선행작업 (코드 1단계의 첫 작업): 디렉토리 rename.** 문서는 `packages/broker-client`를 전제하지만 실제 레포는 아직 `packages/kis-client`다. 코드 1단계의 첫 작업으로 `packages/kis-client` → `packages/broker-client` rename + `pyproject.toml`의 uv 워크스페이스 멤버·의존성 경로 갱신을 한다. 전역 설정 변경이라 세 서비스 영향 범위를 먼저 점검한다(docs/ARCHITECTURE.md 참고).

**전략 (시나리오 1)**

| 단계 | 규칙 |
| --- | --- |
| 진입 자격 필터 | 20일선 > 60일선 **AND** 현재가 > 60일선 |
| 눌림목 포착 | 최근 고점 대비 −5~−10%, 20일선 근처 지지 |
| 반등 신호 (2개 이상 충족 시 매수) | RSI 35 이하 / 볼린저밴드 하단 터치·복귀 / MACD 히스토그램 반등 |
| 분할매수 (3회) | 40% → 30% → 30% |
| 청산 | 익절 +7~10%, 손절 −3~5% 또는 60일선 이탈 |

**포함**
- 대상: 미국 주식, KIS 해외주식 **모의투자(paper)** 계좌(해외 리그).
- 워치리스트 5~10종목, 동시 보유 최대 3 포지션.
- 운영: 미국장(한국 새벽, 대략 23:30~06:00 / 서머타임 시 22:30~05:00)에 engine 가동. **서머타임(DST) 전환 처리.**
- 분할매수 단계·평단가·목표가·손절가 상태 추적.

**제외**
- 실전(real) 매매, 백테스팅 자동화, 종목 자동 발굴/스크리닝.
- 재무·매크로 필터(2·3차), AI 판단(4차).
- 어떤 형태든 LLM이 진입/청산 결정에 개입하는 것.

**다음 단계로 가는 조건**
- paper 계좌에서 워치리스트 등록 → 추세 필터 통과 → 분할 진입 → 익절/손절 청산까지 끊김 없이 동작.
- 의도치 않은 오발주 0건, 상태(분할 단계·평단가) 불일치 0건이 일정 기간 유지됨.

## 청산 고도화 (1차 MVP 이후)

1차 MVP의 **고정 익절(+7~10%)은 그대로 두고**, 그 이후 단계로 청산 방식을 고도화한다. (1차의 고정 익절을 트레일링으로 *교체*하는 게 아니라, 검증 후 *추가/전환 옵션*으로 도입한다.)

**배경**: 고정 익절은 강한 추세에서 추가 상승분을 놓친다. 그렇다고 "감으로 더 들고 간다"는 건 규칙 기반 철학(docs/PRD.md 목표)을 깨므로 허용하지 않는다. 대신 **추세 추적을 규칙으로** 구현한다.

**포함**
- **트레일링 스탑**: 고정 익절 대신, 최고가 대비 −X%(예: 5%) 하락 시 청산. 강추세를 끝까지 타되 판단은 감이 아니라 규칙으로 한다.
- **부분 익절 + 트레일링 하이브리드**: 1차 목표(+7~8%)에서 보유분 절반을 익절(수익 확보), 나머지 절반은 트레일링으로 추세를 추적. 두 방식의 장점을 결합.

**제외**
- 감/재량에 의한 홀딩. 모든 청산은 사전 정의된 규칙으로만 한다.

**트레이드오프**
- 트레일링은 **횡보장에서 고정 익절보다 자주 불리하다** — 작은 봉우리에서 −X%를 찍고 조기 청산되어, 이후 회복분을 놓친다. 강추세에서의 이득과 횡보장에서의 손실을 데이터로 견줘봐야 한다.

**다음 단계(도입)로 가는 조건**
- 1차 MVP가 고정 익절로 충분히 운영돼 매매 데이터가 쌓일 것.
- 그 데이터로 "고정 익절이 놓친 추가 상승분" vs "횡보장에서 트레일링의 조기 청산 손실"을 **백테스트로 비교 검증**한 뒤, 도입 여부·파라미터(X%, 부분 익절 비율)를 결정.

**4차 Hermes 연결**
- Hermes가 "고정 익절이 놓친 추가 상승분"을 데이터로 분석해 청산 방식 변경을 **제안**할 수 있다. 단 **제안까지만** — 실제 변경은 사람 승인 + 백테스트 후에만 적용한다(아래 4차 변경 적용 루프).

## 2차 — 재무 필터 (단순 규칙)

후보군에서 "지뢰 종목"을 걸러내는 안전장치. 여전히 **결정론적 규칙, LLM 판단 없음.**

**포함**
- 적자 지속·부채과다·거래정지(상장폐지) 위험 등으로 판단되는 종목을 워치리스트 후보에서 **제외**하는 규칙 필터.
- 종목 선정의 안전장치 역할(좋은 종목을 고르기보다, 위험 종목을 빼는 데 집중).

**제외**
- AI/LLM 기반 종목 추천, 정성적 재무 해석.
- 신규 종목 자동 발굴(여전히 워치리스트는 사람이 등록).

**다음 단계로 가는 조건**
- 재무 필터가 후보군에 안정적으로 적용되고, 오탐(정상 종목 제외)·미탐(위험 종목 통과)이 수용 범위 안.

## 3차 — 매크로 필터

시장 전체 리스크 이벤트를 인지해 진입을 보수적으로 만든다. **사람 알림까지만, 자동 진입 없음.**

**포함**
- CPI/PPI/FOMC 등 주요 지표 발표 예정일에는 신규 진입 보류("주의 모드").
- 보유 종목 관련 악재 발생 시 **리스크 경고**(알림).

**제외**
- **뉴스 기반 자동 진입은 하지 않는다.** 매크로/뉴스는 진입 보류·경고에만 쓰고, 매수/매도 트리거로 삼지 않는다.
- LLM의 뉴스 해석을 주문 결정에 직접 연결하는 것.

**다음 단계로 가는 조건**
- 주의 모드·리스크 경고가 실제 이벤트에 맞춰 정확히 동작하고, 운영 데이터(매매 기록·수익률)가 분석할 만큼 쌓임.

---

## 4차 — Hermes 분석·제안 레이어 (구상)

운영 데이터가 충분히 쌓인 뒤 도입하는 AI 분석 계층. **매매를 직접 바꾸거나 실행하지 않는다.** 사람이 더 잘 판단하도록 돕는 보조 도구다.

> **용어 주의:** **하네스(`/harness`)** 는 기획 문서를 코드로 옮기는 *개발 자동화 도구*다. **Hermes Agent** 는 운영 데이터를 분석해 제안을 내는 *운영 분석 런타임*이다. 둘은 별개다 — 하네스는 코드를 만들고, Hermes는 매매를 분석할 뿐 코드를 만들지 않는다.

**AI가 하는 것 (O)**
- 매매 기록·수익률 분석.
- 비효율 파라미터 리포트(예: 특정 손절폭이 반복적으로 불리했다는 통계).
- 전략 개선·신규 조건 제안.

**AI가 하지 않는 것 (X)**
- 파라미터 자동 변경.
- 스스로 코드 수정·적용.
- 주문 실행 결정.

**변경 적용 루프 (사람이 게이트)**

```
AI 제안 → 사람 검토·승인 → 하네스로 재구현 → 백테스트 → 적용
```

AI는 이 루프의 첫 칸(제안)까지만 한다. 나머지 칸은 전부 사람과 결정론적 도구가 집행한다.

**멀티 에이전트 구상**
- 섹터 리서처·펀더멘탈·밸류에이션·리스크·알로케이터·트레이드 플래너 등 역할 분담은 이 단계에서 **"리서치 보조"로만** 검토한다.
- 어떤 에이전트에도 **매매 결정권을 부여하지 않는다.** 산출물은 사람이 읽는 리포트·제안이다.

**포함**
- 위 "AI가 하는 것"에 해당하는 분석·리포트·제안 생성.

**제외**
- 위 "AI가 하지 않는 것" 전부. 특히 사람 승인 없는 파라미터/코드/주문 변경.

**시작 조건**
- 1~3차가 안정 운영되고, 분석에 쓸 매매 기록·수익률 데이터가 의미 있는 양만큼 축적됨.
